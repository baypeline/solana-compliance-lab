# 이상거래 발표자료

`index.html` 하나에 글꼴·그림·분석 결과를 포함한 발표자료입니다. 설명 페이지는 클릭할 때마다 정해진 다음 전개가 나타나는 선형 발표이고, 6페이지는 실제 React FE 컴포넌트와 내장 JSON을 사용하는 오프라인 상호작용 데모입니다. 12개 주제 안에 33개 전개 상태가 있습니다. 설명과 데모 모두 HTML 하나로 실행되며 FE 서버·Backend·RPC 연결이 필요 없습니다. 모든 화면은 같은 밝은 바탕과 짙은 도식 영역을 사용합니다. 지갑·수신자·제재 목록의 역할, 관찰한 근거, 판정 결과를 그림 안에서 구분하고 각 전개에 짧은 해석을 함께 표시합니다. 제목은 명사형으로 통일했습니다.

## 발표 순서

개념 → 구현과 실제 사례 → 대응의 유효 범위 검증의 흐름입니다. 실제 FE 시연 2분을 포함해 약 9분 15초 분량이며, 조작·전환을 포함해 10~12분을 목표로 합니다. 분산 송금 설명 뒤에 서비스 시연을 배치하고, WARN 결과 확인 후 별도의 제재 주소 BLOCK 사례로 전환합니다.

| 화면 | 제목 | 시간 |
| --- | --- | --- |
| 1 | 이상거래 | 20초 |
| 2 | 거래 흐름 분석 | 35초 |
| 3 | 탐지와 대응의 구분 | 35초 |
| 4 | 규칙 기반 탐지 | 40초 |
| 5 | 분산 송금 사례 | 1분 |
| 6 | 온체인 분석 시연 | 2분 |
| 7 | 위험 신호와 정책 판단 | 45초 |
| 8 | 서비스 제출 통제 | 45초 |
| 9 | 제출 경로의 차이 | 35초 |
| 10 | 증명 조건과 포함 의무 | 50초 |
| 11 | 블록 유효 조건 | 35초 |
| 12 | 대응의 유효 범위 | 35초 |

Constellation은 실제 네트워크에서 잘 작동하는지를 입증하는 단계가 아닙니다. 팀 리서치의 40%·60% 규칙을 반영한 오프체인 모델에서 대응의 유효 범위를 검증합니다. 제출 경로, 묶음 포함 의무, 전체 참여 조건을 세 화면으로 나누어 설명합니다.

## 발표 전용 오프라인 데모 — 2분

6페이지는 FE의 디자인과 근거 표·모델 결과 컴포넌트를 재사용한 **발표 전용 분석실**입니다. 일반 FE의 자유 입력 폼과 라우팅을 재현하지 않고, 발표에서 유효한 사례와 저장된 조건만 조작합니다. 로그인·케이스 저장·수량·자산·정책 버전·LIVE·임의 조건 입력은 제외했습니다. 데이터와 결과는 `data/demo.json`을 HTML 내부의 JSON으로 포함하며, 코드·스타일·글꼴도 내장합니다. 네트워크는 `connect-src 'none'`으로 차단합니다.

| 순서 | 조작 | 설명 | 목표 |
| --- | --- | --- | --- |
| 1 | 기본 분산 송금 → 분석 결과 열기 | 저장된 35점·MEDIUM·WARN | 25초 |
| 2 | 판단 근거 확인 → 전체 근거 12건 펼치기 | 처음에는 앞선 4건, 필요할 때 전체와 원본 근거 공개 | 40초 |
| 3 | 정상 기준·제재 주소 일치 선택 | 동일 정상 지갑 비교 ALLOW / 제재 레이블 직접 일치 BLOCK | 25초 |
| 4 | 제출 경로 → BLOCK 사례로 통제 비교 | WARN에서 사례 전환을 명시하고, 두 경로 버튼으로 결과 비교 | 20초 |
| 5 | 하단 다음 단계 | 후반 통제 설명으로 복귀 | 10초 |

제출 경로·Constellation 탭은 WARN·ALLOW 사례에서 지원되지 않는 실험을 실행하는 대신 **BLOCK 사례로 통제 비교** 버튼을 표시합니다. 한 번에 사례를 바꾸고 해당 탭의 저장된 결과를 엽니다. Gateway는 적용·미적용 두 경로만, Constellation은 5개 저장 조건과 두 모델만 제공합니다. 새로운 결과를 계산하거나 오류를 거쳐 진행하지 않습니다.

사례 변경이나 뷰 전환 시 스크롤을 위로 복원하며, 데스크톱에서는 사례·탭 조작부가 스크롤 중에도 유지됩니다. **시연 처음으로**는 기본 분산 송금과 공개 전 결과, 기본 경로·모델 조건을 복원합니다. 상위 **데모 초기화**는 화면 전체를 재시작합니다. 시연 안의 클릭·스크롤·방향키는 발표를 넘기지 않으며, **하단 다음 단계 화살표**로 발표를 계속합니다. 다른 페이지를 다녀와도 데모 상태를 유지합니다.

발표 연결 멘트: “저장된 실제 온체인 기록과 분석 결과를 직접 비교했습니다. 분산 송금은 WARN, 제재 주소 일치는 BLOCK입니다. 이제 같은 차단 요청이 제출 경로에 따라 어떻게 달라지는지 살펴보겠습니다.”

정상 기준은 동일 정상 지갑을 양쪽에 둔 기준 확인입니다. 분산 송금의 전체 근거는 여러 유효 시간 창의 합집합이며, 제재 주소 사례의 조회 범위에는 자금 전송이 0건입니다. 이 해석과 저장된 판정은 변경하지 않습니다.

**검증:** 발표 전용 테스트는 결과 공개·4건/12건 근거 펼치기, WARN→BLOCK 전환과 두 경로, 39.99%/40% 및 참여율 조건 비교, 사례 변경·처음으로 복귀, 네트워크 미호출을 확인합니다. 브라우저에서도 실제 조작을 검증합니다.

## 화면의 정보 배치

눈썹 제목, 도식 상단의 배지, 하단 조작 안내·진행 순서, 작은 출처·버전 문구는 본편에서 제거했습니다. 주요 제목·도식·판정·해석을 남기고, 작은 조건 각주 중 중요한 내용은 본문 해석에 합쳤습니다. 상세 출처·버전·조건은 출처 창과 발표 메모에서 확인합니다.

## 첫 페이지 자동 재생

첫 페이지는 거래 기록 → 탐지 → 정책 판단 → 서비스의 제출 통제 → 다른 경로의 가능성을 약 8초 동안 재생합니다. 탐지·판단·서비스 통제 지점에서 각각 약 1초씩 머문 뒤 다른 경로로 이어지며, 마지막 상태에서 약 3초간 대기한 뒤 처음부터 반복합니다. Home이나 첫 페이지 재진입으로 다시 재생합니다. 재생 중에도 클릭·오른쪽으로 다음 페이지로 넘어갈 수 있습니다. 첫 페이지를 벗어나면 재생을 중단합니다. 모션 끄기 또는 모션 줄이기 설정에서는 완성된 그림을 바로 표시합니다.

## 조작과 선형 전개

- 설명 본문 클릭 / Space / 오른쪽 / Page Down: 다음 전개 (6페이지는 하단 화살표로 이동)
- 왼쪽 / Page Up: 직전 전개. 현재 주제의 첫 전개에서는 이전 주제의 마지막 전개로 복귀
- 휠 아래·위: 다음·이전 전개
- Home·End: 전체 발표의 처음·마지막 전개
- N: 현재 전개의 발표 메모, F: 전체 화면, M: 모션 전환, T: 12분 타이머

6페이지를 제외한 설명 본문에는 조작할 선택지가 없습니다. 반복 송금·탐지 규칙·KYT/Policy/Gateway·실제 전송 근거·정책 결과·제출 경로·증명 조건은 미리 정한 순서로 진행합니다. 출처·발표 도구는 보조 창이며 발표 경로를 바꾸지 않습니다. 하단은 페이지 번호와 이동 화살표만 표시하며, 전개 번호는 발표 메모에서 확인합니다.

주소 `#5.3`은 5번째 주제의 3번째 전개를 뜻하며 `#5`는 그 주제의 첫 전개입니다. 정상 발표 중에는 주소를 직접 조작할 필요가 없습니다. 열린 창에서는 클릭·휠로 본문을 넘기지 않습니다. 긴 화면은 내용을 먼저 스크롤하며, 경계에서 새 휠 동작으로 전개를 전환합니다. 관성으로 여러 전개를 건너뛰지 않도록 했습니다.

발표 메모는 현재 전개에 맞는 설명 포인트와 주제 전체의 참고 설명을 함께 보여줍니다. PDF 인쇄는 각 주제의 마지막 전개와 연구 모델 비교표를 출력하고, 인쇄를 마치면 원래 전개 상태를 복원합니다.

## 데이터와 해석

메인넷 수집본 FIXTURE 분석 3건, 정책 판단 3건, 저장·재조회한 Gateway 2건과 Constellation 10건을 `data/demo.json`에 보관했습니다. HTML은 결과를 표시하며 위험도·정책·프로토콜 판정을 재계산하지 않습니다.

분산 송금 사례는 2026-11-09 00:00~03:00 UTC(종료 제외)의 거래 15건·전송 20건을 재분석한 결과입니다. 서버는 RAPID_FAN_OUT, 35점·MEDIUM을 반환했습니다. 각 클릭으로 누적하는 앞선 네 근거는 111초 안의 서로 다른 네 수신자입니다. 전체 근거 전송 12개·거래 서명 7개는 여러 유효 시간 창의 합집합이며 하나의 300초 구간에 있다는 뜻은 아닙니다. 급여·보상 지급도 같은 패턴일 수 있고 점수는 불법 가능성의 확률이 아닙니다.

가상 1 SOL 송금 요청의 정책 결과는 분산 송금 WARN, 제재 주소 레이블 직접 일치 BLOCK입니다. 제재 주소의 조회 범위에는 자금 전송이 0건이므로 실제 불법 송금 탐지 사례로 설명하지 않습니다. 동일 비교 지갑을 양쪽 평가에 사용한 ALLOW 기준 확인은 원본에만 보관합니다.

10화면은 리더의 제외 유효성을, 11화면은 전체 참여 조건을 분리해 표시합니다. 참여 기준 충족만으로 전체 블록이 유효하다는 뜻은 아닙니다. 60% 조건의 저장된 실행은 리더의 제외 시도 때문에 블록이 무효입니다. 상세 입력·판정·감사 ID와 추가 50%/60% 조건은 출처의 JSON과 인쇄 부록에 남겼습니다.

## 편집과 검증

- `src/deck.html`: 12개 화면과 도구
- `src/deck.css`: 밝은 본문·공통 도식 영역, 글꼴·탐색·인쇄
- `src/visuals.css`: 그림·상태·모션
- `src/deck.js`: 선형 상태 이동·클릭/휠/키보드·현재 전개 메모·출처·발표 도구
- `src/visuals.js`: 정해진 전개에 따른 그림·근거·서버 결과의 순차 표시
- `../apps/frontend/src/presentation/`: 발표 전용 분석실·내장 JSON·컴포넌트 테스트
- `vendor/offline-demo.js`, `vendor/offline-demo.css`: 실제 FE의 생성 번들
- `src/notes.json`: 주제별 설명, 33개 전개별 발표 포인트와 화면 해석
- `data/demo.json`: 서버 실행 결과

```sh
python presentation/export_data.py --backend http://127.0.0.1:8080
python presentation/build.py
python presentation/verify.py
```

HTML을 사용하는 데 서버나 빌드 도구는 필요 없습니다. `build.py`는 저장된 FE 번들을 사용해 HTML을 다시 조립합니다. FE 코드를 수정했다면 개발 컨테이너를 시작하고 `python3 presentation/build_demo.py`로 번들을 갱신한 뒤 HTML을 조립합니다. 일반 FE 빌드와 분리된 Vite `presentation` 모드를 사용합니다.

데이터 재수집은 개발 서버와 프로젝트의 계약 검증용 Python 환경이 필요합니다. 데이터 수집·검증에는 `jsonschema` 의존성이 필요하고, HTML 조립 자체는 표준 Python 3으로 실행합니다. 외부 출처와 실제 대시보드는 링크를 클릭할 때만 연결합니다. 데이터 재수집도 실제 Solana 거래를 전송하지 않습니다.
